## 확인된 직접 영향

- 원본 함수 4618개를 정규화 후 비교했다. 기존 함수 중 main만 변경되었으며 GSRI_Init 호출 한 줄 추가가 전부다. 신규 함수 19개는 모두 GSRI 이름이고 생성 소스와 설치본이 일치한다.
- war3map.w3a, war3mapSkin.w3a, war3map.w3u, war3map.w3e, war3map.w3i는 원본과 바이트가 같다. 데미지·쿨다운·유닛·지형·맵 설정 데이터 변경은 없다.
- 추가 코드에 피해, 이동 명령, 능력치 쓰기, 시야 부여, 안개 해제, 아이템/경제 수정 호출이 없다. 실제 피격 판정은 기존 함수 그대로다.
- Splats/LightningData.slk는 전역 리소스이므로 변경 영향 범위가 GSRI 함수 안에만 한정되지는 않는다. 기존 293개 셀은 모두 동일하며 GSRL 한 행 14셀만 추가했다. 기존 번개 ID 수치 변경은 없으나 엔진 로딩/그래픽 호환성은 별도 게임 검증 대상이다.

## 우선 검토 사항

### P1: 초기화 중 마우스 이벤트 등록

main에서 GSRI_Init를 직접 호출하고 그 안에서 EVENT_PLAYER_MOUSE_MOVE/DOWN을 등록한다(src/RangeIndicator.template.j:414). 동일한 등록 시점에 대한 로딩 종료 무렵 ACCESS VIOLATION 재현 보고가 있다. 보고된 버전은 2.0.3.23175이며 현재 빌드에서 재현한 것은 아니다. 따라서 현재 맵이 반드시 충돌한다고 단정하지 않는다. 등록을 게임 시작 후 타이머 콜백으로 지연하고, 여러 명이 로딩 중 마우스를 움직이는 재입장 시험을 우선 수행해야 한다.

근거: [작성자의 최소 재현 코드 및 회피책](https://us.forums.blizzard.com/en/warcraft3/t/20323175-mouse-events-ub-crash/37517). [후속 보고](https://us.forums.blizzard.com/en/warcraft3/t/mouse-events-and-getters-are-causing-crashes/37954)는 일반 게임 중 충돌 주장을 이후 자기 코드 검증 문제로 수정했다. 일반 마우스 API 사용 자체를 확정 충돌 원인으로 취급하면 안 된다.

### P2: CPU·렌더링·입력 이벤트 부하

풀은 클라이언트당 lightning 384개이며 초당 64회 타이머가 실행된다. 스킬을 표시하지 않을 때 Tick은 즉시 반환하나 마우스 이벤트는 계속 등록되어 있다. 모든 bj_MAX_PLAYERS 슬롯에 등록하며, 로컬 플레이어 필터는 콜백에 진입한 뒤 적용된다. 로컬 필터가 이벤트 전달 자체를 제거하는 것은 아니다. 네트워크 트래픽은 측정하지 않았다.

현재 지원 스킬 중 레인저 W는 원 236구간+경로 99구간이다. 표시 중 초당 약 21440회 구간 함수를 호출하며, 시전자 이동으로 모든 좌표가 바뀔 경우 최대 약 64320회 높이 조회가 가능하다. 이 숫자는 코드의 계산량이며 FPS 측정값이 아니다. 정지 시 캐시로 높이 조회/선 이동은 줄지만 원 좌표 계산, 삼각함수와 구간 루프는 계속 실행한다. 전체 영웅으로 확대해도 한 클라이언트가 모든 영웅을 그리는 구조는 아니므로 이 부하를 인원수만큼 단순 곱하면 안 된다.

우선 보완: 원은 시전자 좌표·반지름 변화 시에만 재계산, 방향 표시도 변경 없으면 외부 루프부터 생략, 실제 참여자만 이벤트 등록 검토, v8/v9/원본에서 같은 장소·카메라·전투 조건으로 프레임시간 비교. 관측 전 성능 저하율을 제시할 수 없다.

### 멀티플레이 동기화: 미검증 배포 조건

lightning·location·timer·trigger·hashtable은 동일한 초기화 경로에서 생성하고 표시 중 로컬 분기로 새 핸들을 생성/삭제하지 않는다. 로컬 좌표와 지형 높이는 선 표시 계산에만 사용하며 원본 게임 변수에 쓰지 않는다. 이 점은 위험을 줄이지만 단독 게임 성공이 동기화 안전성을 증명하지는 않는다. 능력 조회, 로컬 상태, lightning 이동/색상, 선택/채팅/포커스 전환을 포함한 2인 이상 재현이 필요하다. 현재 정적 검토에서 확정적인 데싱크를 재현하거나 입증하지 않았다.

### 조준 정보와 실제 판정의 차이

방향 보간은 수신 좌표에 약 141ms 안에 95% 수렴한다. 엔진 입력 지연은 별도로 더해지므로 급회전 직후 클릭하면 보이는 선과 실제 발사 방향이 잠시 다를 수 있다. 공격 방향을 바꾸는 코드는 없다.

절벽에서 선을 숨기는 것은 렌더링 규칙이며 투사체 충돌/통과 가능성을 뜻하지 않는다. 피격 대상의 충돌 크기를 포함한 정확한 경계 일치는 게임 검증되지 않았다. 시야 밖 지형 높이에 따라 선이 굽거나 끊어지는 정보는 표시되지만, 적 유닛을 조회하거나 노출하는 기능은 없다. 미탐색 검은 영역까지 표시할 때 의도한 정보 범위인지 별도 확인한다.

### 자원·이식·운영 제한

추가 자원은 고정 풀 384개, 타이머 1개, location 1개, hashtable 1개, 트리거 4개이며 반복 시전마다 추가 생성하는 경로는 없다. 이는 무제한 누수 경로가 없다는 정적 확인이지 실제 장시간 메모리 측정 결과는 아니다. 풀이 안 보일 때도 할당은 유지한다.

게임 중 완전히 기능을 끄는 토글은 없다. 취소는 표시만 숨기며 이벤트 구독/타이머는 남는다. 이상 시 원본 맵으로 다시 시작해야 한다. 향후 긴급 비활성화 수단은 별도 보완 대상이다.

최신본 이식에서 기존 투사체 함수 지문과 노네 Q 수치를 확인하지만 모든 원본 시스템 변경을 자동 검증하지는 않는다. 월드 에디터 재저장에는 JassHelper 및 재컴파일 검증이 필요하다. 저장/불러오기·리플레이·관전자도 검증하지 않았다.

## 배포 전 확인 순서

1. 초기화 중 마우스 등록 지연 보완 및 로딩 반복 시험.
2. 변경 없는 프레임의 전체 경계 재계산 제거 후 원본 대비 프레임시간/장시간 메모리 비교.
3. 최소 2인, 이후 실제 인원으로 서로 다른 방향·영웅·채팅·Alt-Tab·죽음·재선택을 반복하여 접속 유지와 표시 격리를 확인.
4. 안개/검은 영역에서 선만 보이고 적 정보·기존 번개 효과에는 변화가 없는지 확인.
5. 급회전 직후 시전, 경계 안팎 표적, 지형·시야 교차 사례 확인 후 최신본 이식.
