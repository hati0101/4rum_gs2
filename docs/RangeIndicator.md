# GSRI 범위 표시 테스트 기술문서

2026-10-09 / ver93 기반 v9 fog / 안개 표시본 게임 내 검증 대기

## v9 시야 밖 범위선

사용자 v8 재시험에서 지형 대응 정상 확인. 추가 요청은 시야 밖에도 시전 원/공격 경계선을 표시하는 것이다. v8 모델의 Unfogged 재질 설정만으로 이 요구가 충족되지 않았다.

v9은 분절 모델을 사용자 정의 직선 lightning GSRL로 교체한다. AddLightningEx 및 MoveLightningEx의 checkVisibility=false를 사용한다. 지형 높이 샘플링, 절벽 구간 생략, 64Hz 방향 보간과 좌표 캐시는 유지한다. 선 폭은 SLK Width=3, NoiseScale=0, 텍스처는 기존 GSRI white.tga다. 기존 맵 Splats\LightningData.slk의 인코딩과 모든 기존 셀을 보존하고 신규 행만 추가한다. 기존 ID 덮어쓰기는 하지 않는다.

시야 부여/안개 해제 함수는 추가하지 않는다. 표시선만 로컬 색상/투명도로 제어한다. 멀티플레이 동기화, 검은 미탐색 구역과 회색 전장의 안개, 실제 선 텍스처·폭·재표시는 게임 테스트가 필요하다. 지형이 이미 정상인 v8을 기준본으로 보관한다.

검증: pjass 통과, 기존 번개 효과 셀 전부 동일·신규 14셀 한 행만 추가, 원본 능력/지형 데이터 동일, 시야 부여 함수 없음 확인. 미변경 MPQ 블록 1061개 보존. 실행본 확인은 채팅 -range → GSRI v9 fog.

API 참고: [AddLightningEx checkVisibility](https://lep.nrw/jassbot/doc/AddLightningEx).

## v8 지형 높이 대응

사용자 스크린샷에서 고저차 구간의 표시 이상을 확인했다. v7은 모든 경계에 시전자 좌표의 지형 높이 하나를 사용하므로, 먼 경계가 지면 아래에 묻히거나 공중에 뜨는 구조였다.

v8은 기존 전체 평면 모델 대신 길이 48 이하의 선 조각으로 원·투사체 경계·중심선을 구성한다. 각 조각의 양 끝 및 중간 지형 높이를 읽고, 끝점 높이에 맞춰 위치·기울기·길이를 설정한다. 시전 원의 다각형 근사 오차는 현재 지원 반지름에서 0.8 미만이다. 선 폭은 길이·경사에 따라 약간 달라진다(평지 최대 약 2.9).

샘플 간 높이 차이가 64를 넘거나 중간 높이가 직선 보간값에서 12를 넘게 벗어나면 해당 조각을 숨긴다. 따라서 절벽에서는 선이 일부 끊기는 것이 의도된 동작이다. 절벽 위·아래를 대각선으로 이어 범위가 떠 보이는 것을 피한다. 수면·다리·장식물 표면에 대한 완전한 투영은 아니며, GetLocationZ 지형 높이 기반 근사다.

효과 384개를 모든 클라이언트에서 동일하게 미리 생성한다(원 최대 256, 경로 최대 128). 표시 좌표가 그대로인 조각은 지형 조회 및 변환을 생략하고, 숨길 때 캐시를 초기화한다. 정지 중 지형 자체가 변형되면 좌표 변경 또는 다시 표시할 때 반영된다. v7의 64Hz 방향 보간은 유지하며 실제 공격/지형 데이터는 수정하지 않는다. 풀은 고정 크기로 추가 누적되지 않지만 v7보다 효과 수가 늘었으므로 실제 FPS 검증이 필요하다.

완료: pjass, MDX 읽기, 지원 반지름별 구간 길이/풀 용량, 경사면 3D 끝점 수학 계산, 절벽·중간 돌출 제외, v7 대비 능력 및 지형 데이터 동일성 확인. 실제 엔진의 기울기/스케일 렌더링과 반복 사용·성능 검증은 미완료다. 평지 → 경사로 → 절벽 위/아래에서 레인저 W와 노네 Q를 회전시키고 원·경로의 묻힘, 공중 부유, 선 폭, 프레임을 확인해야 한다.

기울기 계산 참고: [Terrain-Aligned Special Effect 제작자 구현](https://www.hiveworkshop.com/threads/terrain-aligned-special-effect.358171/).

## v7 방향 보간

아키텍트의 v6 게임 테스트 결과: 노네 Q 표시, 두 번 이상 반복 사용, 채팅 케이스 통과. 남은 현상은 게임 전체 정지가 아니라 Q 방향 표시의 끊김이다.

v7은 입력 좌표 사이의 방향 변화를 0.015625초(64Hz) 간격으로 보간한다. 매 갱신에 최단 각도 차이의 30%를 따라가며 ±π 경계에서도 긴 방향으로 회전하지 않는다. 최초 표시에는 즉시 현재 수신 방향을 사용하고, 취소 시 보간 상태를 초기화한다. 노네 Q와 레인저 W에 공통 적용한다. 도달 거리·폭·공격 판정은 v6와 동일하다.

입력 수신 후 정지한 목표 방향에 약 141ms 이내 95% 수렴한다. 이는 실제 프레임 측정값이 아니라 타이머와 계수에 따른 계산값이다. 엔진 입력 지연 자체를 제거하지 않으며, 부드러움과 맞바꾼 짧은 표시 지연이 존재한다. 빠르게 방향을 바꾼 직후 클릭할 때 실제 공격은 원래 게임 명령의 방향을 따른다. 예측으로 공격 방향을 변경하지 않는다.

표시 빈도 증가에 따른 중복 작업을 줄이기 위해 전체 스킬 탐색은 최초 입력 및 0.125초마다 수행하고, 선택된 능력의 존재/표시 허용 여부는 매 표시 주기에 확인한다. 동일 좌표의 지형 높이는 프레임당 한 번만 읽는다. 수치 검증에서 양방향 ±π 경계, 180도 반전, 정지 목표, 오버슈트 없이 수렴하는 것을 확인했다. pjass 통과 및 v6 대비 능력 데이터/형상 리소스 동일성 검증을 완료했다. 체감 부드러움과 반복 사용 회귀는 v7 게임 테스트가 필요하다.

## 범위와 상태

레인저(어스레이크, Hvwd)와 노네(스펠 인보커, Hkal)만 적용한다. 루리엔 및 전체 영웅 확대는 두 사례 검증 이후 진행한다. 원본 능력치, 피해, 명령 처리, 기존 아군 영웅 패널은 변경하지 않는다. 패널 GSTF_SkillOf 및 능력 오브젝트를 참조해 표시 대상을 선정한다.

v2 사용자 피드백: Q/W/R은 첫 표시 이후 재표시되지 않으며 W 형상과 폭이 잘못 보였다. v6에서는 추론 기반 채팅 상태 토글을 제거하고, 표시 시작 시 Stand 애니메이션을 재설정·정지한다. 반복 변환하던 분절 모델 대신 실제 좌표로 만든 단일 모델을 사용한다. 이것은 수정 후보이며, 실제 게임에서 원인과 해결을 확정한 상태는 아니다.

## 표시 데이터

| 영웅 / 스킬 | ID | 시전 원 반지름 | 추가 형상 |
|---|---|---|---|
| 레인저 Q | A012 | 650 | 없음 |
| 레인저 W | A0O8 | 1800 | 중심 이동 1170, 판정 반경 120의 경로 |
| 레인저 R | A11K | 400 / 450 / 500 | 없음 |
| 노네 Q | A08G | 700 | 거리 825, 시작 전체 폭 250(1레벨) / 300(2~4레벨), 끝 전체 폭 400 |
| 노네 W | A03V | 650 | 없음 |
| 노네 E | A08H | 800 | 기존 게임 지면 범위 표시 유지 |
| 노네 R | A08J | 750 | 없음 |

시전 원은 실행 중 실제 능력 레벨의 ABILITY_RLF_CAST_RANGE를 읽는다. 레인저 W의 1170은 원본 트리거의 30 단위 이동 39회에서 산출했다. 반경 120의 이동 판정을 표현하므로 외곽은 양 끝에 반원이 붙는다. 중심 이동 거리와 외곽 끝 거리는 다르다. 대상 유닛의 충돌 크기에 따른 엔진 판정 보정은 검증되지 않았다.

노네 Q는 ACbf 기반이다. aare의 1레벨은 기본 데이터 125를 상속하며 2~4레벨은 맵에서 150으로 덮어쓴다. Ucs3=825, Ucs4=200이다. 넓어지는 통로를 사다리꼴 외곽으로 표현했으며, 꼭짓점에서 시작하는 부채꼴로 단정하지 않는다. 네이티브 공격의 정확한 실제 피격 외곽과 일치하는지는 별도 확인이 필요하다. v8은 위의 짧은 선 조각으로 명목 경계를 근사한다.

레인저 E의 무제한 사거리와 즉발 D는 제외한다. 공통 제외 목록은 디멘션 도어 A0OB, 데스 프로마이즈 A0T1, 카오스 위치 궁극기 A11L, 에인션트 트리(윗브) 궁극기 A07I이다. 해당 다른 영웅은 이번 테스트 대상 자체에서 제외된다. 다른 특성 스킬 전체를 지원한다고 간주해서는 안 된다.

## 실행 구조와 제한

- 단축키 입력 → 보유 능력 중 등록된 키 탐색 → 본인 선택 영웅 검증 → 0.015625초 간격 표시 갱신.
- 동일 단축키가 중복되면 잘못된 스킬 표시를 피하도록 취소한다.
- 시전/마우스 클릭/선택 해제/Esc/Enter/일부 메뉴 키/30초 경과 시 숨긴다.
- 키 입력 후 마우스를 움직이면 방향 표시를 갱신한다. 마우스 위치 이벤트를 아직 받은 적이 없으면 원만 보인다.
- 명령 아이콘 마우스 클릭으로 진입하는 시전 모드, 키 재지정, 정확한 네이티브 타게팅 상태 추적은 미지원이다. 마나·쿨다운 때문에 실제 시전 불가여도 미리보기가 나올 수 있다.
- 효과 핸들은 모든 클라이언트에 같은 순서로 생성한다. 표시 상태와 변환은 로컬이다. 멀티플레이 동기화 검증은 아직 수행하지 않았다.
- v8은 각 선 조각의 지형 높이를 샘플링한다. 급격한 높이 변화에서는 선 일부를 생략하며, 지형에 완벽히 투영하는 데칼 방식은 아니다.

네이티브 OSKEY 이벤트는 채팅/프레임 포커스 등에 영향을 받는다. 따라서 Enter를 받았다는 사실만으로 채팅 상태를 토글해 유지하지 않는다. 참고: [OSKEY 이벤트 제작자 문서](https://www.hiveworkshop.com/threads/oskey-player-key-event.319903/).

## 검증과 재현 절차

완료: MDX 생성 후 재파싱 및 텍스처 경로 확인, 출력 MPQ 변경 멤버 읽기 검증, 미변경 원본 1062개 블록 보존 확인, 원본 SHA256 불변 확인, 설치 게임 common.j/blizzard.j 기준 pjass 문법 검사 통과.

게임 검증은 다음 순서로 수행한다.

1. 레인저 Q/W/R 각각 표시→취소→재표시를 5회, 시전→쿨다운 이후 재표시를 반복한다.
2. 채팅 입력/닫기 후 위 절차를 반복한다. 안 뜨면 `-range`의 keys/shows/range 값을 기록한다. 이 명령 자체의 Enter는 마지막 취소 사유를 바꿀 수 있다.
3. 레인저 W를 여러 방향으로 조준하고 시전 원과 경로가 동시에 보이는지, 표적이 경계 안팎에서 실제 맞는지 확인한다.
4. 노네 Q 1레벨 및 2레벨 이상에서 시작 폭 차이, 거리 끝과 좌우 경계의 실제 피격 여부를 확인한다.
5. 노네 E의 기존 범위 커서, 다른 스킬 전환, 선택 해제, 영웅 이동·사망을 확인한다.
6. 두 클라이언트에서 다른 플레이어에게 표시가 새지 않는지와 동기화 오류 여부를 확인한다.

## 재생성 및 최신본 이식

```powershell
node tools/range_assets.cjs work/model-tools/node_modules/war3-model
python tools/range_indicator.py INPUT.w3x NEW_OUTPUT.w3x --game 'D:\Warcraft III'
python tools/check_jass.py work/validator NEW_OUTPUT.w3x
```

모델 생성 의존성은 war3-model 4.0.1이다. 도구는 기존 출력이나 입력 덮어쓰기를 거부한다. 이미 GSRI가 들어간 맵 대신 깨끗한 원본에 적용한다. 레인저 투사체 관련 네 함수의 지문과 노네 Q 형상 필드가 변경되면 빌드를 중단하므로, 최신본 변경점을 검토한 뒤 렌더러 수치·감사 지문을 함께 갱신한다. 기본 게임 데이터는 설치된 CASC에서 읽고 사용 버전은 manifest에 기록한다.

변경 멤버: war3map.j, war3map.wct, war3map.imp, MPQ CRC 속성 및 GSRI 모델/텍스처. 능력 오브젝트 파일은 수정하지 않는다. 기존 PKWARE listfile은 보존하고 추가 리소스는 import 목록에 등록한다.

월드 에디터에서 저장할 때 war3map.wct의 GSRangeIndicator 라이브러리 초기화가 유지되도록 JassHelper가 필요하다. 에디터 재저장 후 JASS 재검사와 게임 재검증을 수행한다. 현재 배포 파일은 직접 실행용 war3map.j에도 GSRI_Init 호출이 들어 있다. 최신본 이식·에디터 재저장·멀티플레이·실제 게임 QA 통과는 아직 선언하지 않는다.
