# ver138 디싱크·피와케 E 안정화 검토

대상: 사용자가 첨부한 `GS2vF_ver138.w3x`.
결과: `maps/release/GS2vF_ver138_fix.w3x`. 인게임 이름은 ver138로 유지한다.
수정본 SHA256: `cf801323ec2eb9f3f6360c29ced3077e49dc768ef97c8a86dd56bc39f8e9bef7`.

## 사거리 표시와 산투 Q → 징벌의 칼날

개인별 키/마우스/선택 상태로 실행되는 GSRI 표시 코드에서 `BlzGetUnitAbility` 및 `BlzGetUnitAbilityByIndex`를 호출하고 있었다. 클라이언트별 능력 핸들 접근은 핸들 할당이 달라질 위험이 있으므로, 모든 클라이언트가 동일한 영웅 순서로 실행하는 0.125초 타이머에서 능력 정보를 읽고 숫자만 캐시하도록 변경했다. 로컬 표시는 그 캐시를 읽는다. 능력 습득/변신 직후 정보 갱신에는 최대 0.125초가 걸릴 수 있다.

아이템 사거리 표, 41개 아이템 매핑, 아이템 슬롯/단축키/호버 감지, 명령 이벤트 등록, 아이템 사거리 조사 타이머 및 표시 도형을 보존했다. 산투 물약 투척과 이미 분리된 아이템 추가 피해 타이머도 그대로다. 당시 영상의 디싱크 원인이 이것이라고 확정한 것은 아니다. 영상에는 실제 Game Desync 경고가 표시되지만 엔진 로그·멀티플레이 재현은 없다.

실행 스크립트 `war3map.j`와 에디터 헤더 `war3map.wct`의 기존 GSRI 코드가 서로 달랐다. 최근 아이템 표시 수정이 에디터 헤더에는 빠져 있어, 최신 실행 스크립트를 기준으로 GSRI 함수 31개와 전역 선언을 일치시켰다. 이는 헤더에 없는 아이템 조사 함수를 복원하는 작업도 포함한다. 전체 월드 에디터 저장/재생성은 이 Linux 환경에서 검증하지 못했다.

## 피와케 E

`A0NJ`는 공장(ANsy) 기반 능력이다. 기본 `war3map.w3a`에는 이미 생성 주기 Nsy1=86400초, 생성 유닛 지속시간 Nsy3=10초가 적용돼 있었다. 그러나 우선 적용될 수 있는 `war3mapSkin.w3a`에는 4레벨 모두 두 값이 0이었다. 스킨 쪽 8개 필드를 기본 데이터와 동일하게 맞췄다. 추가 생성 주기를 로봇 수명보다 길게 둬 0초 생성 처리를 피한다는 기존 수정 의도를 따른 것이다.

로봇 전용 `GS2PB_Data`, 사망 시 타이머 연결/저장소를 먼저 정리하고 stomp 더미를 생성하는 순서, 기존 로봇 수명·고장 확률은 이미 적용돼 있어 변경하지 않았다. 엔진 내부 0초 생성의 실제 크래시 발생은 여기서 재현하지 못했다.

## 검증과 한계

- MPQ 읽기 및 수정 파일 CRC32 갱신 확인. 변경 대상 외 원본 아카이브 항목 보존 확인.
- 둠로드 텍스처, 유닛/아이템 데이터, 맵 제목, 산투 투척·추가 피해, 피와케 로봇 생명주기 함수 보존 확인.
- 로컬 GSRI 호출 경로에 능력 핸들 조회, 핸들 생성, 전투 상태 변경, 난수 호출, 동기화 캐시 쓰기가 없음을 정적 확인.
- Warcraft native를 모사한 수치 회귀 검사: 41개 아이템 × 6슬롯, 능력 표시 정보 377개, 누락/중복 키·숨긴 버튼·즉시 Channel 등 628개 비교 통과. 실제 게임 렌더링 검사는 아니다.
- pjass로 원본과 수정본 전체 스크립트 문법/타입 검사 통과. pjass `378a1ca9af3848fbc3be3d17069bcdb6a940ee32`, jassdoc API `8610958b3b77b8213f9db45ab664458650a07294` 사용. API 주석만 제거했으며 선언/함수는 변경하지 않았다. 설치 게임의 API 추출본은 아니다.
- 선택적 `+shadow` 검사에서는 원본·수정본 모두 기존 `buff`, `button` 변수명 2건이 보고된다. 새 경고가 추가되지 않았으며 이 옵션을 끈 기본 문법/타입 검사는 통과한다.
- 실제 Warcraft 실행, 멀티플레이 디싱크, 엔진 크래시, 월드 에디터 재저장 검증은 미실행이다. 완전 해결을 보증하지 않는다.

재현 테스트: 모든 참가자가 동일한 수정 맵을 사용하고 산투 Q 직후 징벌의 칼날을 반복 사용한다. 다른 참가자가 별도의 스킬/아이템 사거리 표시를 동시에 사용하는 상황, 산투 변신/부활/스킬 습득 직후도 확인한다. 피와케 E는 1~4레벨, 정상 수명/빠른 사망/고장 특성 상태를 비교한다. 최근 수정한 아이템 각각을 단축키·클릭·호버로 확인한다.
