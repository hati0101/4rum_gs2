# 195-14 — 업화의 열기 실제 유닛 추적과 상시 마나 연소

사용자가 **195-13**에서 “업화의 열기는 공격해야만 마나가 줄고 정지 중에는 줄지 않는다”고 제보했습니다. 툴팁은 공격을 요구하지 않으며, **파이어 엘리멘트 E 레벨에 따라 주변 250의 적 마나를 초당 4/6/8/10 연소**, **마법 피해 감소량 +7%p**입니다.

## 기존 코드에서 확인한 것과 원인 판단의 한계

기존 GS294_BurnTick은 이미 1초 주기이고, 코드에 공격 조건은 없습니다. 따라서 “공격 조건을 발견해 삭제했다”고 말하면 잘못입니다. 기존 방식은 `udg_HeroPlayer[1..12]`에 든 영웅만 처리하고, 연구 완료 처리는 별도의 전역 `udg_Hero_FlB`를 사용했습니다. 이 참조가 실제 제어하는 투마와 다르면 처리 대상에서 빠질 수 있습니다. A0UG 자체의 네이티브 마나 재생 수치는 0으로 되어 있어, 스크립트가 처리하지 않은 유닛에게 이 오라 객체만으로 지속 연소가 생기지는 않습니다.

이번 제보의 실제 런타임 원인이 영웅 배열 불일치라고 엔진에서 재현한 것은 아닙니다. 대상 마나 재생·면역·실제 등록 상태도 함께 확인해야 합니다. 그 참조 의존성을 없애고, 실행/차감을 구분할 진단을 추가한 수정입니다.

## 사용자가 확인한 재현 조건

195-13 싱글플레이에서 투마를 선택하고 마네킹 켈후(Utic)를 소환해 확인했으며, 평타가 들어갈 때만 마나 감소가 보였다는 제보입니다. `GS163_SpawnDummy`는 생성 직후 마나를 최대치로 한 번 채웁니다. 이 함수에는 반복 마나 충전이 없습니다. 이것만으로 다른 회복 경로나 관찰 원인을 배제할 수는 없습니다. 켈후 마네킹, 테스트 모드와 켈후 능력은 변경하지 않았습니다. 동일한 조건에서 투마 E를 배운 후 업화 특성을 찍고 250 안에서 공격을 멈춘 채 `-업화진단`의 활성/대상 수/최근 차감량을 확인합니다. 실제 엔진에서 기존 제보를 재현하거나 해결을 확정한 것은 아닙니다.

## 변경

- 실제 **Odrt / 투마** 유닛을 별도 그룹으로 추적합니다. 시작 시 맵의 기존 유닛을 1회 조사하고, 이후 맵 진입·영웅 판매·스킬 습득·부활 이벤트에서 등록합니다. 환영은 제외합니다.
- 반복 처리는 이 그룹만 확인합니다. 공격 이벤트, 공격 대상, 현재 명령, `udg_HeroPlayer`, `udg_Hero_FlB`를 연소 발동 조건으로 사용하지 않습니다. 매초 맵 전체 유닛을 다시 검색하는 방식도 아닙니다.
- R04B가 연구됐고 E가 1~4레벨인 살아 있는 투마는 매초 **250 범위 적 마나를 4/6/8/10** 차감합니다. 마나가 모자라면 0까지 차감합니다. 공격·이동·피격 여부를 요구하지 않습니다.
- 기존 대상 규칙(적/생존/건물·기계·마법 면역·무적 제외)은 유지합니다. 아군과 시전자 자신은 태우지 않습니다. 피해 이벤트나 HP 피해를 만들어 마나를 태우지 않습니다.
- A0UG 표시 오라와 A11Q 마법 피해 감소를 실제 E/특성 상태에 동기화합니다. E만 있으면 A11Q 내부 단계 E, R04B가 있으면 E+1로 유지해 기존 +7%p 구성을 지킵니다. 단계가 바뀔 때만 갱신합니다. E가 없으면 두 보조 효과를 제거하고, 특성이 없으면 연소를 멈추고 기본 마법 감소 단계로 돌아갑니다.
- 연구 완료 시에는 연구 유닛 소유자의 실제 영웅들을 찾아 등록/동기화합니다. 이미 특성을 찍은 뒤 영웅을 만들거나 E를 배우는 순서도 처리합니다. 기존 연구 이벤트/조건은 유지하며 해당 연구 액션만 교체합니다.
- 사망 시 연소하지 않고 부활 뒤 다시 작동합니다. 실제로 제거되거나 다른 유형으로 바뀐 추적 유닛은 그룹에서 정리합니다.
- 기존 GS294 반복 타이머 생성 코드는 새 초기화 호출로 교체합니다. 중복 초기화 방어로 **반복 타이머는 1개**만 생성하며, 시작 조사용 0초 원샷 1개는 실행 뒤 파괴합니다. 그룹 2개와 등록 이벤트/지역은 맵 수명 동안 쓰는 고정 객체입니다. 시전마다 타이머·그룹·이벤트를 늘리지 않습니다.

## 진단과 마나 재생

`-업화진단`은 본인 기록의 최근 E/특성/활성 단계, 처리 주기, 범위 내 대상 수, 실제 수행한 최근 마나 차감 합계를 표시합니다. 현재 주기와 기록 주기를 같이 표시해 오래된 기록인지 구분합니다. 기록이 없으면 전체 추적 투마 수와 주기부터 표시합니다. 이 명령은 유닛을 등록하거나 효과를 활성화하는 우회 명령이 아닙니다.

마나 연소와 대상의 마나 재생은 별도입니다. 연소 4를 수행해도 그보다 큰 재생이 있으면 화면상의 마나 총량은 늘 수 있습니다. `최근차감합`은 SetUnitState 전후 이번에 차감한 값의 합이며, 마나 재생을 포함한 장기 순감소량이나 피해 성공을 뜻하지 않습니다. 여러 대상이 있으면 합계입니다. 사망/변신 후에는 마지막 활성 기록이 남을 수 있으므로 기록 주기를 확인해야 합니다.

## 보존 및 검사

- **W 195-13 시전 경로와 진단, 신타·레인저 및 다른 영웅, 아이템 구매/조합/재료·재고, 사거리 표시를 유지**했습니다. 오브젝트 데이터 파일(.w3a/스킨/.w3u/.w3q/.w3t)과 WTS는 전부 195-13과 바이트 동일합니다. 툴팁 문구도 바꾸지 않았습니다.
- 기존 런타임 함수 중 기능을 바꾼 것은 GS294_Init / GS294_BurnTick / Trig_FlB_Special_1_Actions의 새 함수 호출뿐이며, 나머지는 버전 문구 외 동일함을 대조했습니다. 에디터 라이브러리에도 같은 새 처리와 연구 액션 설치를 포함했습니다. 전체 월드 에디터 재저장은 미검증입니다.
- 전체 JASS 문법 및 에디터 추가 코드의 전처리 후 독립 문법 검사 통과.
- 추출된 실제 새 함수 모사: 공격 API와 기존 영웅 배열을 아예 제공하지 않은 상태에서 E 1~4레벨 정지 연소, 250 경계/밖, 대상 필터, 선 연구·후 E, 낮은 마나, 특성 손실, 사망·부활, 환영/제거 유닛 정리, 실제 소유 유닛 연구 등록을 검사했습니다. 초기화를 두 번 호출해도 1초 반복 시계 하나와 파괴되는 시작 타이머 하나만 생기는지 확인했습니다.
- 활성 MPQ 1,069개 유지. 변경은 런타임·에디터 스크립트·제목·CRC 속성 4개 파일뿐입니다. 나머지 1,065개 파일은 압축 해제한 내용이 같습니다. 정리 전후 내용·CRC·코드 블록 길이를 확인했습니다. 복구 리소스는 삭제하지 않았습니다.
- 실제 Warcraft 게임 엔진 실행은 하지 못했습니다. **공격하지 않고 서 있는 실제 투마의 주변 적 마나 차감은 195-14에서 재확인이 필요합니다.** 이 수정으로 다른 미확인 스킬이나 교전 멈춤 문제까지 해결됐다고 주장하지 않습니다.
