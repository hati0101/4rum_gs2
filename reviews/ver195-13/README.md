# 195-13 — 투마 W 실제 시전자 경로 교체

## 사용자가 확인한 실패와 이전 수정의 한계

195-10/195-11/195-12 모두 투마 W의 공속 버프·마나 소모·쿨다운·폭발 모델은 나타나지만, 폭발 피해와 감속은 적용되지 않는다고 사용자가 실전 확인했습니다. 따라서 이전의 마나/범위 보강은 **해결되지 않은 수정**으로 기록합니다. 정상 동작을 확인하지 못한 상태에서 설정값 검사만으로 실제 시전 경로의 문제를 해결하지 못했습니다.

## 확인한 구버전 범위와 설명 가능한 부분

첨부된 옛 맵 8개뿐 아니라 저장소의 현재 트리에 보존된 원본/패치/137~146/195-7 이후 맵 23개도 비교했습니다. `timeline.json`에 각 파일 SHA256, W 액션 원문, A0CV/h00W/AHtc 객체 원시값을 기록했습니다. 중간 버전이 전부 보존된 이력은 아니며, 보존되지 않은 파일이나 다른 채팅방 파일은 읽을 수 없습니다.

- 1.07 / 1.5005: `ewsp`가 A0CV의 실제 시전자이며 수치로 된 `852096` 명령을 보냅니다. 당시 다른 스킬 ID·피해량은 현 버전에 그대로 복사하지 않았습니다.
- 1.5605 / vF_1 / vF_3Fix2 / vF_4: 폭발 모델을 가진 h00W가 A0CV의 시전까지 맡습니다. 명령 `$D0080`은 852096입니다.
- vF_8 / 저장소 F8FIX / ver19~52 패치: h00W 시전 구조이며 명령은 thunderclap입니다.
- 137~146 / 195-7·8·9: 위치를 정리하는 기존 래퍼 차이 외에 이 액션 본문은 같습니다. A0CV 내부 필드 일부 누락과 이후 Htc5=0 처리도 비교했습니다.
- 195-10·11·12: 마나/범위는 명시됐지만, h00W + GetLastCreatedUnit + 유닛 생성 후 GetSpellAbilityId 조회의 기존 시전 구조는 유지됐습니다.

이 비교로 **정확히 어느 버전에서 처음 고장났는지나 네이티브 시전 실패의 유일한 원인을 확정하지는 못했습니다.** “봇이 원인” 또는 “마나가 유일한 원인”이라고 단정하지 않습니다. 공통 이벤트/엔진 상태와의 상호작용 가능성도 남습니다.

## 이번 변경

이번에는 설정 누락만 추가하는 대신 **실제 시전자 경로를 바꿉니다.**

1. 시전자의 핸들·소유자·좌표·W 레벨·R048 연구 수를 **어떤 더미도 생성하기 전에 로컬 변수에 저장**합니다. A0CP를 직접 읽고, 유닛 생성 뒤의 GetSpellAbilityId/GetTriggerUnit/GetLastCreatedUnit에 실제 시전을 맡기지 않습니다.
2. h00W는 기존 3초 폭발 연출로 남겨 둡니다. 실제 시전은 오래된 1.07/1.5005에서도 쓰던, 현재 맵에서 마나 1000인 `ewsp`를 별도로 생성해 수행합니다. 이 시전자도 3초 수명이며 핸들을 로컬 변수로 유지합니다. 시전점/후딜은 0, 마나는 최대치로 설정하고 기존 A0CV를 부여합니다.
3. 기본은 내부 레벨 1~4, R048이 연구되면 5~8입니다. 연구 수가 비정상적으로 2 이상이어도 선언된 8레벨 밖으로 보내지 않습니다. 특성 강화는 기존 1회 강화(+100, +50%p)입니다.
4. 실제 능력 부여/레벨을 확인한 뒤 구버전의 숫자 명령 `852096`을 **이 로컬 시전자에게 딱 한 번** 보냅니다. 별도 직접 피해를 덧붙이지 않아 두 번 피해가 들어가는 경로를 만들지 않습니다.
5. A0CV만 대상으로 기본/스킨 양쪽에 선언 레벨·단위 능력 여부·마나·범위·지속시간·대상·피해·감속·공격속도 감속 0·기존 최대 피해 0 정책을 명시합니다. 구버전에서 특성 레벨 5~8의 Htc4도 0이었음을 확인해 함께 복원했습니다. 이 더미는 매 시전 새로 생성하므로 내부 쿨다운/시전 지연은 0으로 명시합니다.

| 스킬 레벨 | 일반 피해 / 감속 | R048 피해 / 감속 |
|---|---|---|
| 1 | 40 / 15% | 140 / 65% |
| 2 | 80 / 20% | 180 / 70% |
| 3 | 120 / 25% | 220 / 75% |
| 4 | 160 / 30% | 260 / 80% |

모든 구간 범위 300, 감속 1.5초, 기존 적 생체 지상 대상입니다. 영웅 A0CP의 공격속도 버프·5초 지속·마나 75/90/105/120·쿨다운 12초, 특성 구매와 수치, 다른 영웅·아이템 구매/조합·사거리 표시·복구 리소스는 유지했습니다. 교전 멈춤 문제는 이 패치로 해결됐다고 주장하지 않습니다.

## 실제 명령 확인: -투마진단

W 시전 후 `-투마진단`을 입력하면 본인에게만 마지막 W의 기록을 표시합니다.

- `내부=실제/요청` — 예: 특성 보유 W 4레벨이면 8/8
- `부여=1` — UnitAddAbility가 true를 반환했음
- `명령접수=1` — IssueImmediateOrderById가 true를 반환했음. **실제 피해 적용까지 성공했다는 뜻은 아닙니다.**
- `피해설정/범위/감속설정` — 시전자 능력 핸들에서 직접 읽은 값. 예: 260 / 300 / 0.8

시전 기록이 없거나 설치가 확인되지 않는 경우도 구분합니다. 명령이 거절되면 성공으로 표시하지 않습니다. 요청하지 않으면 채팅/화면에 매번 출력하지 않습니다. 진단 기록은 플레이어별 마지막 문자열 1개만 저장하고 더미 핸들을 영구 저장하지 않습니다. 새로운 전역 피해 리스너나 시전마다 반복하는 타이머는 추가하지 않았습니다.

## 에디터 코드 반영

Flame_Burst는 WCT의 개별 사용자 스크립트가 아니라 GUI에서 생성된 액션이므로 WCT 문자열 교체만으로 갱신할 수 없었습니다. 새 실행 함수와 초기화 후 해당 트리거의 액션만 교체하는 코드를 WCT 라이브러리에 넣었습니다. 이벤트/조건은 유지하며, 다른 트리거를 일괄 지우지 않습니다. 현재 배포 스크립트와 에디터용 초기화 모두 같은 함수를 설치합니다. 초기화는 한 번이며 시작 시 0초 원샷 타이머 1개를 실행/파괴합니다. **전체 맵의 다른 수많은 런타임 확장까지 포함한 월드 에디터 재저장 결과는 미검증**입니다.

## 검증과 남은 확인

- 런타임 전체 JASS 문법 검사 통과. 에디터 추가 라이브러리는 전처리 래퍼 제거/전역 선언 재배치 후 독립 JASS 문법 검사 통과(전체 vJASS/월드 에디터 빌드 검증과 다름).
- 실제 새 함수로 60개 모형: W 1~4레벨 × 연구 수 0/1/2 × 정상/능력 부여 실패/레벨 설정 실패/명령 거절/시전자 생성 실패를 실행했습니다. 유닛 생성 중 이벤트 컨텍스트와 BJ 마지막 유닛을 다른 값으로 오염시켜도 저장한 시전자/레벨로 명령하는지 확인했습니다. 이것은 재진입 견고성 검사이며, 실제 엔진에서 그 오염이 이번 문제의 원인이었다고 증명한 검사는 아닙니다.
- 초기화 중복 방지, 특정 GUI 트리거의 액션 설치, 명령 실패 진단을 검사했습니다. 모형이 true를 반환했다고 실제 게임 작동 성공으로 간주하지 않습니다.
- A0CV 외 모든 능력, 영웅/유닛/특성/아이템/문자열 파일과 나머지 함수 보존을 비교했습니다. 활성 MPQ 1,069개 전부 유지, 정리 전후 내용 동일/CRC/에디터 블록 길이를 검증했습니다.
- 실제 Warcraft 실행 환경은 없습니다. **195-13에서 주변 적의 체력 감소와 감속까지 실전 확인해야 합니다.** 실패가 남으면 W 사용 직후 `-투마진단` 출력으로 발동 누락·능력 부여·레벨·명령·로드된 수치를 구분할 수 있습니다.
