# 195-9 — 195-8 기준 누수·반복 표시 비용 보강

기준은 사용자가 제공한 `GS2vF_ver195-8.w3x`입니다. 마지막 실전 플레이본 195-7도 함께 비교했습니다. 이번 작업은 실제 지연 원인을 단정하거나 FPS 향상을 측정한 작업이 아니라, 코드에서 확인한 누수와 반복 작업을 줄인 1차 최적화입니다. 실제 Warcraft 실행 환경은 없습니다.

## 두 업로드의 비교

- 195-7 → 195-8에서 바뀐 활성 파일은 `war3map.j`, `war3map.w3i`, `(attributes)`뿐입니다. 스킬/영웅/아이템/특성/스킨/배치/리소스 파일은 모두 동일합니다.
- 함수 597개 삭제, 3개 추가, 14개 변경입니다. 삭제 597개는 봇 관련 596개와 사용하지 않는 기존 피해 정리 콜백 1개를 합한 수치입니다. 함수 목록은 `baseline-comparison.json`에 기록했습니다.
- 봇 함수 삭제, 초기화 호출 제거, 판다 전용 검색 분리 및 64개씩 피해 추적 정리 분산은 195-8 상태를 유지합니다. 삭제된 함수는 에디터 WCT의 사용자 정의 함수에도 남아 있지 않습니다. 이는 모든 에디터 재저장 결과를 검증했다는 뜻은 아닙니다.

## 이번에 수정한 부분

1. **네임드 피해 조건의 검색·그룹 누수**: `Trig_Named_Damage_Add_Conditions`에서 매번 중립 적대 플레이어의 전체 유닛을 열거하고 그룹을 해제하지 않았습니다. 기존 포인트 조건을 유지하고 소유자를 직접 비교합니다. 정상적인 이벤트 대상에서 같은 소유자 판정을 하며, 해당 검색/임시 그룹을 만들지 않습니다.
2. **버려지는 임시 위치 34곳**: 소환/돌진/시작 위치와 아이템 접근 판정에서 즉석 생성한 위치를 기존 소유권 정리 래퍼로 넘깁니다. 특히 인벤토리가 가득 찼을 때 아이템에 접근하는 반복 검사와 썬더 리자드 돌진에서 두 번째 위치가 남던 경로를 정리합니다. 아이템 픽업 거리 170, 돌진 거리/충돌 판정, 반복 간격은 바꾸지 않았습니다. `verification.json`에 34곳의 호출/인자를 기록했습니다.
3. **별도 위치 3개**: 위치 교환(`Trig_Change_Actions`)의 스냅샷 위치 2개를 교환 완료 후 해제하고, `Trig_AbW_Special_1_Actions`의 위치 1개도 사용 뒤 해제합니다. 대기 시간·대상·좌표·시전 명령은 유지합니다.
4. **원샷 타이머 예외 경로 3곳**: `GS181_RainProc`의 시전자 누락, `GS181_FxEnd`의 이펙트 누락, `GS181_FlakExpire`의 출처 유닛 누락 때도 해당 타이머와 자신의 저장소를 정리합니다. 정상 효과의 지속시간/피해/마나는 바꾸지 않습니다. 유닛 삭제가 반드시 null로 읽힌다는 가정도 하지 않습니다.
5. **팀원 패널 표시 비용**: 레벨/쿨다운 글자와 체력/마나 막대가 같으면 중복 설정을 생략합니다. 쿨다운 글자를 매번 지웠다 다시 쓰는 동작을 한 번의 최종 표시로 바꿨습니다. 슬롯 위치는 생성 때 배치하고 루트 위치는 화면 비율이 바뀔 때 갱신합니다. 표시 주기 0.1초, 값·색상·쿨다운 반올림·궁극기 준비 강조는 유지합니다. 캐시는 로컬 표시에서만 사용하며 게임 판정에 읽히지 않습니다. 패널 재생성 시 초기화합니다.
6. **무작위 피해 출처 그룹**: 트롤 관련 기존 코드에서 `GroupPickRandomUnit(GetUnitsOfPlayerAll(...))`로 버려지던 그룹 2곳을 회수합니다. 기존 랜덤 선택을 그대로 1회 호출하며 BJ 그룹 소유권 플래그도 존중합니다.

## 보존 범위

- 195-8의 1,069개 활성 MPQ 항목을 모두 읽고 대조했습니다. 변경 파일은 런타임 스크립트, 에디터 사용자 스크립트, 맵 제목 정보, CRC 속성뿐입니다. 나머지 활성 파일 1,065개는 압축 해제 후 바이트가 같습니다.
- 능력/특성/아이템/상점 객체, 조합 DB·구매·재고·조합 코어, 전투 피해/쿨다운/난수 호출, 사거리 표시, 드래곤 워리어 복구 자료는 보존합니다. 아이템 접근 판정은 결과를 유지하며 임시 위치 소유권만 바꿉니다.
- 봇을 되살리지 않습니다. 사거리 표시도 꺼서 성능을 얻는 방식은 사용하지 않았습니다.
- 새 제목/시작 안내/디버그 표기는 `195-9`입니다. 에디터 스크립트에 존재하는 수정 함수는 같이 반영했습니다. 기존 GUI 트리거/컴파일 결과와 모든 런타임 확장 전체를 월드 에디터에서 재저장해도 유지하는지는 미검증입니다.
- MPQ의 교체된 payload/테이블 잔여 공간만 정리했습니다. 활성 파일과 복구용 리소스를 삭제하지 않았고, 정리 전후 모든 활성 파일의 내용이 같습니다. 195-8 자체도 이미 정리된 파일이므로 새 코드 때문에 결과가 약간 커질 수 있습니다.

## 검사와 결과

- `pjass` 전체 JASS 검사: 원본 195-8 및 수정본 통과. 검사기와 API는 각각 lep/pjass 및 lep/jassdoc에서 가져왔으며 실제 설치된 게임 API로 실행한 검사는 아닙니다.
- 추출된 실제 함수를 모사 실행했습니다. 정지 상태의 5인 패널을 100회 갱신할 때 텍스트 쓰기 **4,500 → 25회**, 막대 크기 설정 **1,000 → 10회**. 매 갱신의 최종 표시 상태가 같습니다. 실제 FPS/실제 10초 측정값이 아닙니다.
- 패시브/미습득/쿨다운/마나 부족/영웅 변경 및 빈 슬롯 등 1,000개 모형 상태 전환, 막대 경계값, 패널 캐시 초기화 검사 통과.
- 아이템 거리 검사 10,000회 모형에서 해제되지 않는 위치 **10,000 → 0개**. 거리 계산 결과는 유지됩니다. 실제 게임 누적 메모리 사용량 측정은 아닙니다.
- 네임드 소유자/포인트 조건, 위치 교환 좌표·0.75초 대기, 타이머 누락 경로, 무작위 선택·BJ 소유권 플래그와 난수 호출식 보존 검사 통과.
- 원본/결과 SHA256, 수정 함수 목록, 크기는 `verification.json`, 전체 코드 차이는 `script.diff`에 기록했습니다. `build.py`로 재생성하고 `test_regression.py`로 모사 검사할 수 있습니다.

## 실전 비교

195-9에서 평소 멈추던 시간대까지 플레이하고, 같은 시점의 195-8과 비교해야 합니다. 기존 `-성능` 명령은 유지됩니다. 시작/10분/20분/멈춤 직후 화면과 리플레이를 남기면 다음 병목 조사에 도움이 됩니다. 이 명령의 피해 추적 수는 전체 핸들 수나 모든 누수량을 나타내지는 않습니다.

여럿이 같은 순간 멈추는 현상은 네트워크 지연일 수도 있고 동기화된 스크립트 처리일 수도 있어, 그 사실만으로 서버 원인이라고 결론낼 수 없습니다. 특정 PC만 화면이 끊기는지, 싱글플레이에서도 재현되는지, 어떤 스킬/아이템/시간대인지 함께 비교해야 합니다. 전역 상태를 공유하며 대기하는 옛 스킬이나 재시전 취소 경로는 별도의 실전 재현 없이 일괄 재작성하지 않았습니다. 짤렉·멈춤이 완전히 없어졌다고 보장하지 않습니다.
