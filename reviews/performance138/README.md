# ver138 전체 트리거 정적 검토와 1차 최적화

기준: `maps/release/GS2vF_ver138_fix.w3x`.
테스트용 수정본: `maps/release/GS2vF_ver138_opt.w3x` (인게임 이름은 ver138 유지).
SHA256: `c3a039a8bc8d4894e25db0b721dcb7cb45c5a807dae3368d66d7001757071f45`.

전체 JASS 함수 4,739개를 정적으로 분류했다. `function-inventory.tsv`는 모든 함수와 기준 줄 번호, 자원 생성/열거/대기/로컬 문맥 표식이다. 이 목록에 표시됐다는 이유만으로 누수라고 판정한 것은 아니다. 생성한 자원이 다른 함수에서 정리되거나 게임 종료까지 유지되는 것은 정상일 수 있다. `periodic-triggers.tsv`는 주기 트리거 등록 16건이다. 별도로 TimerStart 기반 동작도 추적했다. 함수 173개에 대기 처리가 있다.

## 확인해서 수정한 문제

1. 추종 `MakeUnitFollow_Sub`, 넉백 `Knockback_Action`, 디바인 스트라이크 `Trig_Divine_Strike_Sub`의 종료 시 해시테이블 정리 키 순서 오류. 저장은 `(timerId, StringHash(field))`인데 삭제는 `(StringHash(field), timerId)`였다. 따라서 삭제 호출 50개가 실제 기록을 지우지 못했다. 올바른 타이머 ID의 자식 테이블을 한 번에 정리하고 타이머를 정지·삭제한다. 추종 종료의 유닛 제거 순서와 원래 종료 조건은 유지한다.
2. 추종 이동이 0.04초마다 위치 객체를 생성·삭제했다. `SetUnitPositionLoc`은 내부에서 같은 좌표로 `SetUnitPosition`을 호출하므로, 목표 유닛 X/Y를 직접 읽어 같은 이동을 수행한다. 1개 추종 유닛당 초당 25번의 임시 위치 객체 생성/삭제를 없앴다. 이동 주기, 경로 탐색을 적용하는 이동 API, 방향 및 수명을 유지한다.
3. 궁신 `Trig_Gungsin_Actions`의 4개 호출에서 위치를 소비하는 GS2V84 정리 래퍼를 사용한 뒤 호출부도 같은 위치를 삭제했다. 호출부가 이미 소유한 위치는 원래의 BJ/네이티브 함수에 빌려주고, 호출부에서 한 번 삭제하게 맞췄다. 전투 수치는 변경하지 않았다.
4. 피와케 특수 광선 `Trig_GoT_Special_3_Actions`, 타르타로스 이동 `Trig_Tartaros_Come_on_Actions`가 `AddLightningLoc`에 즉석 생성한 위치 두 개를 넘기고 삭제하지 않았다. BJ 함수는 이 위치를 정리하지 않는다. 새 helper가 두 위치를 정리하며 원래 번개 모델, 지형 Z, bj_lastCreatedLightning, 번개 수명/삭제 처리는 유지한다.
5. 공통 `d_effect`는 호출마다 CreateTrigger/TriggerAddAction/TriggerExecute 후 PolledWait로 대기하고 임시 트리거를 삭제했다. 호출 지점은 49개이며 범위 스킬은 한 번에 여러 번 실행할 수 있다. 전용 해시테이블과 1회 타이머로 이펙트 소유권/기한을 보관하고 정리한다. 임시 트리거와 대기 스레드를 제거했다. 양수 수명당 타이머 1개는 여전히 필요하다. 0 이하 수명은 즉시 삭제하며, 기존 PolledWait의 지연·반올림 대신 요청한 시간이 타이머 기한으로 쓰인다. 이는 시각 이펙트 정리 시점 차이이며 실제 엔진에서 외형 확인이 필요하다.

전체 변경은 기존 함수 8개와 새 helper 1개, 전용 해시테이블 전역 선언이다. 맵 객체 데이터(능력/유닛/아이템/특성/수치), 사거리 표시 GSRI 전체, 기존 41종 아이템 감지·표시, 팀 패널 GSTF, 영웅 선택 GSPF, 산투 GS2S, 피와케 로봇 생명주기는 그대로다. 내부 파일은 war3map.j/war3map.wct와 CRC 메타데이터만 변경했다.

에디터 헤더와 해당 사용자 지정 코드 블록의 helper 수정도 반영했다. 생성된 GUI 트리거의 직접 수정은 런타임 스크립트에 적용됐으며, 원본 WTG는 변경하지 않았다. 전체 에디터 재저장 후 결과는 미검증이므로, 다시 저장한 맵은 반드시 별도 비교/테스트해야 한다.

## 검증

- pjass 전체 JASS 문법/타입 검사 통과. API 기준과 선택적 shadow 경고 한계는 `reviews/ver138/README.md`와 동일하다.
- 원본 종료 함수를 모사 실행하면 세 저장소 기록이 남는 오류가 재현되며, 수정 함수는 타이머 관련 기록을 모두 삭제하고 다른 부모 키 기록은 보존한다.
- 추종의 좌표·방향·종료 경계(remaining >= 0) 비교 일치. 4회 이동에서 임시 위치 객체 생성이 4→0으로 감소.
- 이펙트 10,100건 모사 실행: 독립 기한, null/0 수명, 타이머 ID 재사용 후 잔여 타이머/저장소 0 확인.
- 함수 비교로 GSRI/GSTF/GSPF/GS2S 및 로봇 처리 보존 확인. 아카이브의 수정 대상 외 블록 보존 확인.
- 위 모사 검사는 실제 Warcraft 네이티브를 실행하지 않는다. FPS·프레임 시간·메모리·멀티플레이 디싱크는 미측정이다. 후반 렉의 단일 원인이나 모든 트리거 오류를 해결했다고 주장하지 않는다.

## 추가 측정이 필요한 부분

- 넉백은 여전히 25Hz에 임시 아이템을 생성·삭제해 이동 가능한 좌표를 구한다. 이를 단순 SetUnitPosition으로 바꾸면 충돌/이동 동작이 달라질 수 있으므로 이번에는 보존했다.
- 이동·투사체 등의 0.03~0.04초 트리거는 대체로 필요할 때만 켜지고 끝나면 꺼진다. 주기를 무조건 늘리면 스킬 동작이 달라지므로 변경하지 않았다.
- 동적 피해 이벤트 구독/거리 이벤트, 사거리 표시 수치 캐시(8Hz), 표시 렌더링(64Hz), 팀 패널 갱신은 실제 부하 측정 대상이다. 기존 저장소/그룹 정리 함수가 있으므로 영구 누수라고 단정하지 않았다.
- 사거리 표시가 특히 필요한 사용자 요구 때문에 아이템 호버/명령 감지·표시 기능을 제거하거나 전투 중 렌더링 주기를 낮추지 않았다.
- 오래된 GUI 트리거의 전역 임시 변수, GetLastCreatedUnit/Effect 공유, 대기 이후 사건 값 사용은 동시 시전 재현이 필요한 후보군이다. 무조건 전체를 자동 치환하지 않았다.
- 살아 있는 유닛 수, 소환물·시체·오브젝트 수, 광역 피해에 따른 트리거 연쇄와 그려지는 이펙트 양은 실제 후반 리플레이에서 비교해야 한다.

동일 참가자/그래픽 설정/시간대/전투 구성을 맞춰 기준 ver138_fix와 opt를 비교한다. FPS 저하인지 여러 참가자의 진행 지연인지 구분한다. 30~60분 경과 후 추종/소환, 반복 넉백, 디바인 스트라이크, 피와케 광선, 타르타로스, 범위 이펙트, 아이템 사거리 표시를 확인한다. 효과가 없는 경우 이력과 재현 장면을 기반으로 다음 측정을 진행해야 한다.
